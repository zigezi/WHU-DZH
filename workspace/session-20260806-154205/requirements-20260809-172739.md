# 需求分析

## 一、项目概述
建设一套面向外部客户的 YOLO 目标检测可视化前端页面。页面需支持单路 RTSP 监控流实时检测与本地视频文件上传检测两种模式，通过调用后端已有 API 以流式方式获取检测结果，并在视频画面上实时绘制检测框、类别及置信度数值。页面需具备直观的可视化效果与简洁的操作体验，客户无需技术背景即可独立使用。

## 二、目标与用户
### 目标用户画像
- **角色**：外部客户，非技术背景人员。
- **特征**：不熟悉算法与工程细节，期望开箱即用的可视化展示；关注检测效果的直观性、页面美观度与操作简易性。
- **使用场景**：通过浏览器访问页面，查看实时监控画面的 AI 检测结果，或上传自有视频验证检测效果。

## 三、功能需求
- **FR-01 实时监控模式**
  - **需求描述**：支持接入单路 RTSP 监控流，前端向后端 API 发起请求并接收流式检测结果，在视频播放区域内实时渲染检测框、目标类别文本及置信度数值。
  - **验收标准**：RTSP 流可正常接入播放，检测框与视频画面延迟在可接受范围内；单屏仅展示一路视频，禁止多路同屏。
- **FR-02 上传视频检测模式**
  - **需求描述**：支持用户从本地上传视频文件，前端将视频发送至后端 API 进行流式处理，并边处理边播放，在画面上实时绘制检测框、类别及置信度。
  - **验收标准**：上传视频后无需等待完整处理即可开始播放并同步显示检测框；支持常见视频格式（如 MP4）[待确认]。
- **FR-03 检测可视化渲染**
  - **需求描述**：在视频画面之上叠加绘制检测边界框，并在框旁或框内显示类别名称与置信度数值（如 `person 0.92`）。
  - **验收标准**：不同类别可使用区分颜色[待确认]；文本清晰可读，不遮挡关键画面；渲染帧率与视频播放基本同步。
- **FR-04 模式切换与页面布局**
  - **需求描述**：页面提供清晰的入口或选项卡，供用户在“实时监控”与“上传视频”两种模式间切换。
  - **验收标准**：客户无需指导即可独立完成模式切换；页面布局简洁，核心视觉区域为视频画布。

## 四、非功能需求
- **性能**：视频播放与检测框渲染延迟应控制在用户可接受范围[待确认具体指标，如秒级或帧级]；页面交互响应流畅，无明显卡顿。
- **可用性**：界面设计面向非技术客户，核心任务操作流程不超过两步；异常状态（如拉流失败、后端无响应、格式不支持）需有明确的文字提示。
- **兼容性**：需明确支持的目标浏览器及版本[待确认]。
- **安全性**：如客户数据涉及敏感画面，需明确是否需要前端脱敏或传输加密[待确认]。

## 五、技术约束与环境
- **前后端分工**：后端 YOLO 推理服务已部署完毕，前端仅负责调用后端 API 并渲染结果，禁止在浏览器端本地运行模型推理。
- **数据交互方式**：前端与后端采用流式数据交互（如 SSE、WebSocket 或 HTTP Chunked）[待确认具体协议]，实时接收检测坐标与置信度。
- **视频源类型**：支持 RTSP 网络监控流与本地视频文件两类输入。
- **部署方式**：[待确认]

## 六、非目标（Non-goals）
- 本次不支持多路监控分屏展示，仅支持单路视频同时展示。
- 本次不包含检测告警功能，如声音提醒、页面弹窗告警、消息通知等。
- 本次不包含浏览器端本地模型推理（如 WebAssembly、ONNX Runtime 等）。
- 本次不包含离线处理模式（即等待整段视频全部处理完成后才展示结果）。
- 用户权限管理、登录认证、检测历史记录与结果持久化保存[待确认]。

## 七、后续任务建议
1. 与后端确认 API 接口规范，包括流式传输协议、请求/响应参数格式、坐标系定义（像素值/归一化值）。
2. 确认 RTSP 流在前端的播放方案（如使用 HLS、WebRTC 转码或直接播放等）及对应的后端对接方式。
3. 确认目标浏览器版本、支持的本地视频格式、视频分辨率与码率上限。
4. 输出交互流程图与 UI 视觉稿，重点设计检测框颜色、置信度字体样式、异常状态提示。
5. 制定前后端联调计划，针对延迟、卡顿、断线重连等场景进行专项测试。
