## 4. 仪器校准注记
- 阶段一/二均落在 20–70% 带内 → v3 基板**命中能力前沿带**（首次）；
- **但观察到的死亡全是 `wrong_fix`（能力型：修而未对）——属"不可拦截"类**（a50 §二）；过程型死亡（test_loop / partial_fix_plateau / premature_done / regression_break）**计数全 0**。

## 5. 关键结论（诚实）
**单发式执行器（一次调用→一个修复）不产生过程性死亡。** 过程性死亡需**多步**：读→跑→定位→修→复跑，及"修好一个弄坏一个""未跑测试就宣称完成"等**跨步状态**。当前执行器是单发，故只映出能力型死亡（wrong_fix），喂不出可拦截谓词。
- 这与 a52 §一机理一致（"过程性死亡需要过程"）：v3 把**任务难度**提到了前沿带，但**执行器仍无过程**，所以尸体多为能力型。

## 6. 谓词候选（§五）
- **无干净候选**：`wrong_fix` 是能力缺口，拦截器拦不出能力（a50 §二）。
- 下一步必须把**执行器**从单发改成**多步 agent 回路**（读/跑/定位/修/复跑 + 测试运行工具），才可能采到过程型尸体——这是 a52 §三.2 封顶条款下的"再上一级"。

## 7. 待裁决
1. 授权**执行器多步化**（单发→agent 回路；属执行器/基板变更，接近封顶条款边界）；
2. 或按 a52 §三.2 记账：**承认当前廉价基板（含单发执行器）够不到过程型死亡**，代码域免疫工作须 SWE-bench 级基板，重新开裁。
