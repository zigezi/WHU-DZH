## LR-4 "存在 ≠ 无害"（与 DC-9 同源，认知侧）
- **事件**：a76 §三 全量回归扫 **79/79 全绿**，却在**清单外**的 E3 旧脚本 `e3_substrate_check.py` 上发现它静默把生产注册表重置回候选态（DC-9）。
- **认知**：**官方清单全绿 ≠ 无污染**。旧脚本的写路径是仪器衰变的盲区维度——与 LR-2"存在≠在岗"同族的另一半：存在≠在岗（没接真实路径）↔ 存在≠无害（接了真实路径却在乱写）。
- **修法**：DC-9 三条结构性封堵（自检沙盒默认 + 回归扫注册表不变性断言 + 封线脚本 attic/manifest）。

## LR-5 二审 finding 的可验证性分级（P5a.82 §二.3）
- **事件**：Qwen3.8-Max 二审 QA-1（`r[9] or "unknown"` 假阳性）零 token 即时证伪；架构类 finding（DC-9 层级绕过）需代码取证后确认。
- **认知**：二审 finding **永远是假设，不是事实**。语言语义类主张可零 token 即时证伪（优先验证）；架构类主张需 grep/取证按流程验证。**验证在前，立法在后。**
- **修法**：findings 分级——① 语言语义类即时证伪；② 架构类走"验证令→回执→立法或销案"；③ 假阳性登记 QB-1（语言语义）/ QB-2（架构）入二审校准档案。

## LR-6 数据入位当日即查 git 边界（P5a.86 §二.4）
