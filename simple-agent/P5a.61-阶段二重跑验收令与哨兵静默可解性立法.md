## 四、对"是否布置针对性触发任务"的裁决：不批

opencode 问：要不要为剩余 3 件未确认守卫（items_count / non_delivered / payment_enforce）在下一批针对性布置触发任务。**不批，理由三条**：

1. **接线电池已经把"失能"从解释空间里排除了**。8/8 经真实 execute_tool 路径全绿，意味着这 3 件守卫生理上能点火。由此立法——**哨兵静默可解性**：自此以后，哨兵不点火的唯一解释是"该模式未发生"，不再是"可能没接线"。这是本轮重跑买到的最值钱的性质，不要浪费它。
2. 追溯审计已知这三类模式活体稀有（items_count 扑救 1/962、payment 良性税 4/962、non_delivered 覆盖 0.5）。为做账而造陷阱烧 token，是把簿记债务伪装成科学问题。
3. 哨兵模式的边际成本≈零：资产随一切未来批次在岗，live_confirmed 自然闭合。

**检查点立法**：自本令起累计 50 个哨兵在岗 run 后盘点；届时仍 False 者，二选一呈裁——靶向小批（≤0.3M）或降级休眠（dormant：保留注册、退出在岗）。持续静默本身是信息，不许烂尾。
