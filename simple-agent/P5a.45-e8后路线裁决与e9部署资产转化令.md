# P5a.45 — e8 后路线裁决：否决三项新增架构，e9 转为首个部署资产

> 触发：用户三选项咨询（规划 agent / skill 增能 / opencode 扒多臂源码优化免疫）。
> 裁决：**三项均不批准以所提形式立项。发热门下的唯一合法动作是 e9 转为部署资产。架构税已在 P5a.24–44 缴清，现在是退税期。**

## 一、三选项裁决

**选项 A（规划性 agent）：否。**

1. e8 刚刚证伪的就是"外源计划结构能帮到执行"——在 τ 上，把一份编号计划骨架塞给 agent 一分都拿不到。此时再建一个"产生计划的 agent"，等于给已证无效的管道换了个更贵的上游；
2. 规划的真实需求场是多步状态变更任务（P5a.41：R-105 类），τ 域该测的已测完；规划问题随 E3/E2 重开，在那里它有真实考场；
3. 发热门现状：部署资产 0。新增架构层 = 分子不动分母加，直接恶化发热比。

**选项 B（skill 增能）：作为免疫通道否，作为资产包装保留。**

1. opencode 源码审查结论在案：skill = 模型按 name+description 自选，无确定性触发字段。免疫功能的教义是确定性触发（P5a.25），把拦截职责交给模型自选 = 把门禁交给门卫的心情；
2. 手写 skill 直接喂能力 = 用户本人警惕过的"黑板行为"——未经金丝雀认证的散文资产，正是免疫系统存在要拦截的东西；
3. 但 skill 作为**已认证资产的最终包装形态**是合理的（opencode 的原生装载点）。顺序是：先有资产，再谈包装。当前资产 = 0。

**选项 C（扒多臂源码优化免疫）：否，收留一个内核。**

1. 免疫系统的精度已不是瓶颈——它刚完成第一次干净的开火。继续优化免疫 = 城堡守得很好、城里没人，且直接违反发热门；
2. **收留的内核**：多臂机器本身（任务级随机化 / 矩阵冻结 / 簇 wild bootstrap / CopyGuard / 运行表 schema）是**域无关的试验 harness**，E3 代码域要原样复用。令 opencode 零 token 整理一页可复用规格存档——这是收割已建成的设施，不是继续优化它。

## 二、发热门下唯一合法动作：e9 → 首个部署资产

e9（锁序拦截器 Path B'）的全部要素都已备齐，无一行新架构：

- **死因已知**：P5a.28 回测——首个 modify 严格先于损害点 0/12，损害 = 首次 modify 执行本身；
- **受害总体已普查**：R-041 / R-072 / R-098 / R-105 / R-058，5 任务；
- **干预形态已立法**：Path B' 否决式（P5a.32），once-per-order 状态位，合成返回"若还需改地址先改地址；否则重新发起即通过"；
- **验证器已登记**：B-2 金丝雀电池（≥5 探针，已知答案），确定性谓词不需要 epoch；
- **预算**：token ≈ 0。

部署后拦截器进入运行时，干预日志自然累积——**系统的第一个活资产，出生证写：validated_domain=τ，死因=锁序，证据=a28 回测 + B-2 电池。**

## 三、给 opencode 的工单（全部零 token）

1. **B-2 金丝雀电池**：≥5 探针，覆盖 5 个锁死任务型，已知答案，判定 = 谓词点火正确性（该拦的拦住、不该拦的不动）；
2. **Path B' 拦截器实现**：按 P5a.32 规格，监控侧持有、确定性、once-per-order 状态位；
3. **多臂 harness 一页规格**：随机化/冻结/bootstrap/CopyGuard/运行表，域无关化存档（E3 基建储备）；
4. **销账**：P5a.44 两张工单（Δ1/Δ3 的簇 CI 补报；R3-138 例 ∩ 55 在用注入物交集清单）。
