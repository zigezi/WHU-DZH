# P5a.25 裁决：沉积物路由与规划边界

**仲裁人：Claude（任务书作者）｜日期：2026-09-29**
**问题**：对比市面传统 harness 范式，除架构税低之外，我们是否需要加入 task 规划来判断"这个任务调哪条沉积物"（T1-T4）？
**裁决：不需要。沉积物选择是路由问题不是规划问题——路由键是触发条件，匹配器必须是确定性的。T1-T4 是信用级别，回答"信不信"，不是路由键，不回答"调哪条"。即便将来规划智能体的四道门全开，沉积物选择也留在确定性路由器手里——规划的归规划，路由的归路由。给路由加 LLM 判断力，等于把这套体系相对传统范式最硬的优势（归因完整性）亲手交出去。**

---

## 一、先纠正问题里的一个概念混淆：T1-T4 不是路由键

P5a.24 的信用级别（T1 同族 / T2 跨族 / T3 跨数据集跨模型）记录的是**证据强度**，存在于溯源层，回答的是"这条资产在该语境下该不该被信任、敢不敢对外声称"。

"这个任务调哪条沉积物"是**匹配问题**，其唯一法定路由键是资产的**触发条件**（P5a.17 F2：触发条件+动作+验证）。

```
正确的问题结构：
  if 触发条件(任务) 在场 → 注入该资产（按其信用级别决定优先级与预算）
  而不是：
  由规划智能体"判断"这个任务"应该"调哪条
```

信用级别唯一合法参与路由的场景：**多条资产同时命中、注入预算不够时的优先级排序**（T 级高者优先）。这是排序参数，不是判断主体。

---

## 二、为什么"规划式路由"恰恰是传统范式的病，不是我们的药

市面 harness 范式的沉积/记忆加载，无非四种，每种都有明确病历：

| 范式 | 加载机制 | 病历 |
|---|---|---|
| 巨石系统提示 | 全部常驻 | 上下文税 + 稀释（P5a.18 R1），规模一死 |
| RAG 检索 | embedding 相似度 | 语义匹配未校准；我们的 precedent 臂就是它的残次品版——占位序列冒充经验，测了四轮空气 |
| 技能路由器 | LLM 自选 skill | 未校准仪器（MR-7）：选择本身不可审计、不可复现，事后归因归零 |
| 微调内化 | 烧进权重 | 不可审计、不可退役、衰减不可见 |

**我们这套相对它们的护城河，从来不只是架构税低，而是归因完整性**：每一次注入决策是确定性函数的输出——可重放、可审计、可写进论文的方法学章节。"注入了 X 因为触发条件 T 命中"是一句话能说清的因果链；"规划智能体觉得该调 X"是一句永远说不清的黑箱断言。

**在沉积物选择环节引入 LLM 规划，等于主动放弃归因完整性，退化成第四种范式（技能路由器），只是名字更时髦。** 架构税省下来的，会在归因税上连本带利还回去。

---

## 三、路由的正确实现：触发条件的确定性编译

沉积物路由 v0（且可能永远是）：

```
路由器 = 确定性匹配器，从资产库的触发条件字段编译而来
  - 触发条件尽可能是机器可判定谓词：
    结构信号（任务含时间差/金额/数量比较）、
    工具信号（即将输出的断言依赖未由工具产出的数值）、
    正则/黑名单（F1 的逆向应用）
  - 命中 → 注入；不命中 → 不注入。决策即日志，日志即证据。
```

**活口（唯一一个）**：有些触发条件本质是语义的，机器谓词会漏（例："两个相距很远的数字是否一致"——投标文件场景——结构上不一定可判定）。那时的解锁物是**一个小型校准分类器**：

-  MR-7 适用：它自己是仪器，先测混淆矩阵（在标注样本上 precision/recall 达标才上岗）；
-  它是**测量仪器**，不是**判断主体**：输出"触发条件在场概率"，决策阈值确定性；
-  混淆矩阵进证据链，漂移即复校。

这与规划智能体的区别：**分类器只回答"在不在场"，规划智能体回答"该怎么办"——前者可校准，后者不可校准。**

---

## 四、规划的归规划，路由的归路由

P5a.18 的四道门仍然有效，规划智能体（若解锁）的职责是**任务分解与步骤排序**——这在投标文件等长程任务中是真需求。但即便它上岗：

```
规划器输出：这个任务分成哪些子任务、什么顺序   ← 步骤的"what/when"
路由器输出：每个子任务执行时哪些资产在场      ← 每步的"with what"

两者正交。规划器永不直接点名沉积物；
它产出的子任务流过同一个确定性路由器，按触发条件匹配。
```

理由：子任务一旦由 LLM 产出，其内容仍然客观——触发条件匹配对任何文本输入都是确定性函数。**规划可以改变任务被切成什么样，但不能改变每条切片该配什么药——药方由失败模式的客观在场性决定，不由规划者的品味决定。** 这样规划智能体即便犯错，错误的爆炸半径也被限制在任务分解层，污染不到注入层的归因链。

## 五、现实的顺序提醒

- 当前库存：**1 条注册资产**（锁序规则候选，P5a.21 登记）。1 条资产的路由问题平凡到不需要路由器。
- 设计按 10-100 资产规模做（本节教义），实现按 1 资产规模做。
- 语义触发器漏检率**被测量到显著**之前（用 e4-e6 的失败 span 回测机器谓词的 miss rate 即可，零新运行），连校准分类器都不许写。
- P5a.18 四道门原样不动；本裁决新增一道针对路由层的门：**机器谓词漏检率未量化前，禁止任何 LLM 参与注入决策。**

## 六、一句话教义

**传统范式把"调哪条经验"交给检索相似度或 LLM 直觉，我们把同一个问题退化成查表——触发条件在场则药在场。低架构税只是表象，真正多出来的是：每一次用药都能开出处方。规划智能体将来负责切任务，但永远不许它开处方。**
