# P5a.69 ring_draft 联调开工令（小额 LLM 预算预注册）

依据：P5a.67 §四（C 类排序第一）、opencode 请示（image 105，预计 <0.1M）、P5a.58（宪法边界）、P5a.68（攒批载体纪律）

## 一、批准开工

ring_draft LLM 起草器联调上线（管线唯一 LLM 格子；双效工单：器官成熟 + 代码尸体来源）。

## 二、预算与闸门

- **硬顶 0.1M tokens**（DeepSeek 小账），运行时闸强制——沿用 a60 §三立法后的 SA_BUDGET_CAP 机制，任务间累计检查，触顶即停；超支需新授权。
- 本预算仅供联调测试，不含任何开采动作。

## 三、测试输入纪律（关键）

联调干跑的输入**只用已有语料**：τ 已裁决候选与负先例（213 条）作为夹具——它们的正确结局已知，可作 known-answer 自检。**不产生任何新开采**：τ 封线有效，代码域未校准，两边都不收新资产；联调产出的草稿一律进**证据域**（.agent/reports/），不部署、不出生、不进注册册。

## 四、宪法边界照旧（P5a.58 重申）

ring_draft 不碰 reward/verifier、不改测试、不自改死因分类法、无 commit/push 权（提交动作归 opencode 工程师身份，不归器官）。

## 五、验收口径（预注册）

联调验收**看走通，不看质量分**：

1. 端到端管线贯通：分诊处置单 → ring_draft → 草稿文件落盘；
2. 草稿要素齐全（预注册清单）：谓词文本 / 点火条件 / **可观测性声明** / 误伤面自评 / 干预语义型标注（良性再发 vs 行为改道）；
3. 草稿质量的高下不判——留给代码域 Phase 1 用真实尸体校准。
