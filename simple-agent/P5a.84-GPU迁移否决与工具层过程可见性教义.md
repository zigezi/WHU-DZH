**裁者**：仲裁席（本席）
**日期**：2026-10-15
**案由**：(一) 用户澄清「API 调用违背判决」的确切含义——PaddlePaddle 生态中 API 端印章流水线只返回结果，本地部署可得完整识别过程，API 的过程黑箱对尸体科学构成一定程度的信息捏造；(二) 用户问：以当前开发进度推算，是否换用带显存的机器进行模型接入与尸体管线适配（兼作智能体物理环境迁移测试），预算上升可接受。

## §一 教义钉界：操作者黑箱与仪器可见性

用户澄清成立，先钉一条永久教义，关闭「API 之争」：

1. **骨干 LLM 是操作者（operator）**。我们研究的对象是它的**行为轨迹**（工具调用序列、退出码、stderr 摘要），从不分析其权重内部——操作者可以是黑箱，正如实验心理学不解剖被试的大脑。API 调用骨干 LLM 无碍尸体科学。
2. **工具层阶段是仪器/环境（instrument）**。死因归因要求仪器过程可见：pytest 的 rc + stderr、钩子的逐命令记录，皆是死因可归因的前提。一个只返回结果的工具阶段 = 该阶段内部死亡不可归因 = **死因黑箱**。用户在 PaddlePaddle 场景指出的「API 端只给结果、本地端给全过程」差异，正是此义——这不是合规问题，是科学仪器问题。
3. 因此：用户「API 调用违背判决」的表述，**字面不成立**（在案无此禁令，P5a.83 §一维持），**精神成立**——工具阶段 API 化确实削弱尸体可分析性。将来若多模态门开启，印章/视觉阶段须本地部署，理由登记为本条教义（可分析性），而非「API 禁令」。
4. 多模态议题的提出顺序不予追溯，问题已闭。

## §二 迁移裁决：否决，留 CPU

以当前进度推算，GPU 需求为零：

| 在跑事项 | 负载性质 | GPU 需求 |
|---|---|---|
| 骨干 LLM（DeepSeek V4.1 Flash） | API 调用 | 无 |
| Qwen3.8-Max 二审 | API 调用 | 无 |
| 器官机器（五环/电池/注册表/钩子） | 纯 Python，CPU | 无 |
| 代码域尸体农场（攒批 6/30） | 文本日志 | 无 |
| E2 epoch-1/2（文本先行，P5a.83 §五） | 文本层 + 评测器 | 无 |

GPU 的唯一用途是 P5a.83 已推迟至 epoch-3+ 候选的多模态线。此外，本机 2 vCPU / 7.3 GiB 从未被任一回合报告为瓶颈——历史超支全部是 token 预算超支（a60 立法针对的），算力超支零记录。**为一个已推迟的候选议题购置硬件，且买的不是当前瓶颈，是否决的充分条件。**

## §三 「物理环境迁移测试」价值鉴定

**鉴定结论：不构成购买理由。**

1. 迁移测试没有预注册研究问题——本项目是判断机制研究，不是部署工程；无假设的运维动作不是实验。
2. env_fingerprint 纪律（P5a.80）的检验价值真实存在，但它的正确检验时机是**迁移因真实需求发生时自然被检验**——指纹系统恰为那一刻而生。为检验指纹系统而制造一次迁移，等于为测试烟雾报警器而纵火。
3. 迁移的真实副产品（运维过程中的真实代码域死亡）不走此通道入账：a68 任务价值检验——迁移若仅为产尸而发起，即制造尸源，禁令适用。

## §四 触发式硬件采购立法

硬件采购与 epoch 推进同纪律：**触发式，无时间表**。

1. 唯一合法触发：某 E 门批准了一项需要本地模型能力的范围（当前候选登记簿上仅有多模态一项，epoch-3+）。
2. 门开之后的**最小损耗迁移窗口** = 该 epoch 的 smoke 先导之前：成本模型本就要在新 epoch 重标定，env_fingerprint 断代集中在 epoch 边界，可比性损耗最小。
3. 现在迁移 = 为可能永远不开的门预付租金。P5a.81 §七 预注册了负结果预案：若 epoch-1 死亡全为能力顶死型，入负结果册、不追加轮次——多模态门有真实概率永不开启。
4. CPU 机器的退役条件另行登记：若未来任一回合报告算力瓶颈证据（非 token 预算），可单独立案，不以本条为限。
