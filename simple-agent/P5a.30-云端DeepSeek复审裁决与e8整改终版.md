## 一、发现层裁决

### 发现 1（A-016 垄断）：方向接受，经验性错误必须纠正
- ✅ 接受：Case 1/2/8/13/15 同 hash（e608098794b52d9a），注入集中度是真实设计缺陷——这正是 a23 增补条款把"注入集中度"升为预注册参数的原因。
- ❌ 纠正："剔除 A-016 后效应可能已在零轴附近"**与已算出的数字矛盾**：opencode 服务器审计实测剔除 A-016 后 Δ=**+13.4pp**、剔 top2 后 Δ=**+11.5pp**——不是零轴附近。触零的是**簇 bootstrap CI [-2.2, +27.1]**（族级推断的区间下沿），那是另一件事。**论断时禁止把"敏感性分析"和"簇稳健区间"混用。**

### 发现 2（U 型迷茫 = 任务不匹配）：接受，且补一个它没看到的信号
接受其解读：人工 U 率高部分源于跨域注入（A-016 航班延误赔偿 → 零售改商品/退换货），标注困惑反映注入物与任务的真实错配。**补充观察**：3 例 S 中唯一 S+PASS 是 case 9（R-052←R-000，**同域**），两例跨域 S（case 5、18）均 FAIL——样本内暗示"结构迁移可能需要同域"，这是族精细化（P5a.9 修订）的方向性线索，但 n=3，只登记不行动。

### 发现 3（高频 A = 把注入物当现成答案）：接受
与 P5a.29 终审完全一致（self 通道 6/9 判 A），无需补充。

### 发现 4（S 类是唯一有价值的资产）：方向接受，状态降级为假设
"脱敏工具骨架 = 唯一可能的真实价值"方向正确——这正是 e8 Δ2 要测的命题。但注意：**3 例 S 中 2 例 FAIL**，S 标签 ≠ 有效。"骨架有价值"目前是假设，e8 三臂 + 脱标识是它的审判庭。

## 二、整改层裁决

### 整改 1（全量脱标识为抽象骨架 `<RES_ID>`）：✅ 已是法律
P5a.28/P5a.29 已强制（实体抹除、工具序列保留），其格式示例与本裁决一致。收敛确认，无新增动作。另纠正其措辞"你已经晚了"——**e8 尚未运行**，脱标识令先于任何 e8 token，没有废纸产生。

### 整改 2（CopyGuard 抄袭熔断）：⚠️ 改造后接受——是审计仪表，不是结局改写器
其原版"参数撞注入物值 → 直接判 FAIL"有两处违法：
1. **奖励函数不可动**：τ-bench 结局 = DB 状态哈希 + 输出匹配，中途改写结局定义 = 研究中途换仪器，e6/e7/e8 可比性全毁；
2. **误伤合法路径**：agent 经本任务工具调用重新查出的值与注入物恰好相同，是合法重演不是抄袭。
**法定版本（采纳 P5a.29 §四.3 定义）**：CopyGuard = **"注入值出现在 agent args 且未曾在本 run 先前工具结果中出现"** 的审计检测器，产出污染计数进分析层。脱标识注入物下预期命中 = 0；**任何命中 = 脱标识 lint 失效 = 仪器 bug → 该例隔离开案**，不改结局。

### 整改 3（平衡注入分布、破垄断）：✅ 接受，定机制如下
- 注入物复用上限 **k=3 / content_hash**（预注册参数）；
- 臂分配仍为任务级随机；臂内注入物选择为**受限随机**（同族合格池内无放回抽取，耗尽则标记 ineligible 并记录——不跨臂递补，保持处理定义干净）；
- opencode 开工前产出最终 注入物×任务 矩阵并入预注册冻结件，集中度（top-k 覆盖率）随结果报告。

### 整改 4（System Prompt 加"严禁抄答案"死命令）：❌ 驳回
三条理由，任一条都足够：
1. **混淆处理定义**：e8 测的是"注入通道本身的因果效应"。加禁令后，效应 = 注入 × 指令顺从 的混合体，永远无法归因；
2. **抄袭行为是因变量不是 bug**：我们要测的恰恰是 agent 面对先例的自然行为（CopyGuard 测它）；用 prompt 把行为压掉 = 把体温计砸了退烧；
3. **自我违宪**：往每个任务的 system prompt 永久注入一条未经验证的规则文本，恰是 P5a.17 宪法禁止的 L0 式巨石注入——用自己的手违反自己的法。
脱标识后注入物本无值可抄，该条款在内容上亦无的放矢。

## 五、修订（同日）：云端 DeepSeek 三约束裁决——三条全部采纳，写入 e8 预注册

云端 DeepSeek 对本裁决（引 P5a.29）提出三条反对意见。裁决：**三条均成立**，其中第 1 条纠正仲裁人的修辞错误，第 2 条是对已立法项的规格补强，第 3 条为新的方法学约束。e8 预注册相应修订如下：

### 5.1 e7 解读勘误（采纳）：跨域 sibling ≠ 脱敏器
P5a.29 §2.2"天然脱标识器"是修辞过度，撤销。准确表述：**e7 sibling 臂是异质处理**——同域骨架（结构相关、值不可迁移）与跨域异物（结构亦异质，更接近安慰剂）的混合物，两成分不可分离。e7 结案结论（无证据）不变且更稳；**对 e8 设计的推论：sibling 臂必须限同域**，否则测的不是"骨架迁移"。

### 5.2 e8 预注册修订 A：sibling 臂同域约束（新增）
- sibling 注入物选择降级链：**同域同族 → 同域近族 → 标记 ineligible 记档**（不得跨域递补，不得跨臂递补）；
- 开工前矩阵冻结时报告同域覆盖率；**若同域同族覆盖率 <60%（sibling 臂任务中），opencode 回报仲裁人再裁，不得擅自放宽**。

### 5.3 e8 预注册修订 B：脱标识实现规格（立法确认 + 规格细化）
采纳"占位符替换而非删除"（P5a.30 §二整改 1 已是此义，现固化为规格）：
- 类型化占位符词表固定：`<RES_ID> <ORDER_ID> <USER_ID> <FLIGHT_NO> <DATE> <AMOUNT> <NAME> <PAYMENT_ID>` 等；
- **同一注入物内同一实体映射同一占位符**（保共指结构——`get_reservation_details` 的 `<RES_ID>` 与后续步骤的 `<RES_ID>` 必须同号，否则骨架的语法锚点断裂，此即"模型崩盘"风险的正解）；
- lint 双检：(a) 无残余实体值；(b) JSON 可解析、工具名合法、共指一致。纳入用户抽检 5-10 例的检查项。

### 5.4 e8 预注册修订 C：unrelated 臂形态匹配（新增，采纳第 3 条）
- 每条分入 unrelated 臂的任务，注入物从**异族池**抽取时按形态匹配该任务的"假想 sibling"：**序列长度 ±2 且工具类型多重集近似（首工具类型优先）**；无精确匹配取最近邻并记录距离；
- 开工前产出**两臂形态平衡表**（长度/类型分布对比）入预注册冻结件；
- Δ2 解释随之收紧为：**形态对消后的内容相关性效应**——这正是主终点应有的定义。

### 5.5 驳回其流程要求
"更新预注册后再跑全样本量化审计"——不成立。全样本量化审计（P5a.29 §四）作用对象是 **e7 的 72 条既有注入**，与 e8 配置无依赖关系，两者并行。审计不必等，e8 不必让路。
