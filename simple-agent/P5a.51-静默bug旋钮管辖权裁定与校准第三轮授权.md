# P5a.51 — 静默 bug 旋钮管辖权裁定与校准第三轮授权

> 触发：e3-pilot-stage1-v2.md——v2 修 bug 形态两轮失败率 0.0%（bugs=1 → bugs=2 调整用尽锁死），opencode 停跑上报，问：切"可见测试比例"旋钮属参数调整还是设计变更？
> 裁决：**属参数调整（旋钮切换），不是设计变更。授权校准第三轮（静默 bug 配置），预注册唯一允许的调整路径。**

## 一、管辖权裁定

**判据：任务形态是否改变。** v2 的形态定义是"坏模块 + 隐藏单测判分 + 修复目标参考解"——可见测试给多少、给哪些，不改变形态，只改变模型可得的信息量。且"可见测试比例"本就列在 P5a.50 §三的立法旋钮清单里。**裁定：旋钮切换 = 参数调整，裁决人授权即可，无需重走基板规格程序。** 相对地，模块行数→多文件、任务前提变更（不告知有 bug）之类才构成设计变更。

**先例条款（供未来引用）**："每阶段一次调整"纪律的目的是防中途悄调难度污染普查，不是捆死校准本身。校准探针阶段的每次调整须**逐次授权、记录、锁死**——opencode 两轮即停上报，程序满分；本次授权为第三次校准，同样规则。

## 二、诊断确认与第三轮配置

opencode 的根因诊断采纳：**可见测试=隐藏测试子集时，坏模块被当场照出，模型复跑即修——这不叫任务，叫开卷考试。** 过程性死亡的栖息地确实是静默 bug：可见全过、仅隐藏边界失败、模型无失败信号可依赖。那时才会出现我们要的尸体：premature_done（找不到就宣称修好了）、wrong_fix（猜错位置）、overfix（乱改一通把可见测试也弄坏）。

**第三轮（v2.1）授权配置**：
- 可见测试 = 仅 happy-path（**剔除一切边界断言**）；
- 变异算子限边界/微妙类（off-by-one、边界条件、整数溢出类），剔除"明显逻辑错"类；
- 10 题探针（8 自构造 + 2 金丝雀同配置），冒烟先行照旧。

**预注册调整路径（防往返）**：若失败率 >70%（静默过度、信号全灭），唯一允许的调整 = **放回一条边界测试**（部分信号恢复），记录锁死；若仍 0.0%（模型凭推理就能定位边界 bug），唯一允许的调整 = 同族注入第 2 个静默 bug。两者之外出带 → 停跑上报，那时再审模块行数/多文件（届时承认是设计变更）。

## 三、记录在案

- token 累计 6,149 = 预算 0.77%——两轮校准烧得比 e8 零头的零头还少，校准纪律本身就是资产；
- 金丝雀在两轮 0% 下无读数属预期（仪器在低难度无信号），第三轮同配置继续带。

## 四、一句话

**开卷考试测不出学习能力，闭卷才行——但闭太狠就成了猜谜。第三轮：把边界断言收进暗袋，只留 happy-path 在明处。**
