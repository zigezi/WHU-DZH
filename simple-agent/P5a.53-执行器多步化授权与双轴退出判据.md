# P5a.53 — 执行器多步化授权与双轴退出判据

> 触发：e3-pilot-stage1-v3.md + 死亡报告——v3 命中前沿带（3/14 = 21.4% ∈ [20%, 70%]），但 3 具尸体全是 wrong_fix（能力型），过程型死亡全 0；opencode 自诊"单发执行器无过程"；用户："过程可能短了"。
> 裁决：**授权执行器多步化（选项 1）。封顶条款不触发——它管难度轴，v3 难度已达标；当前缺的是过程轴。预注册双轴退出判据，防新跑步机。**

## 一、验收

- v3 首次命中 20–70% 前沿带，难度校准完成。四轮校准史：v1 形态不够 → v2 信号太露 → v2.1 静默仍不够 → v3 真实仓库+变异注入命中；总耗 41,739 tokens = **预算 5.2%**，每个结论都有收据。
- 死亡报告诚实采纳：wrong_fix ×3（能力型，不可拦截，拦不出能力）；test_loop / partial_fix_plateau / premature_done / regression_break / syntax_death / env_corruption 全 0。诊断一致：**单发执行器没有过程，尸体只能是能力型。**

## 二、管辖权澄清（重要先例）

封顶条款（P5a.52 §三.2）管的是**难度轴**的跑步机——追不上难度就停。v3 难度已达标，**封顶不触发**。当前问题在另一条轴：**过程轴**。τ 的过程型死亡（锁死、重复风暴）诞生于多轮工具循环；若 τ 的执行器也是单发的，那些死亡同样不存在。所以本次变更的对象是**执行器**，不是难度、不是基板形态——三个轴不许混为一谈，各自的调整纪律独立记账。

## 三、执行器多步化（授权正文）

- **agent 回路四工具**：`read_file` / `run_visible_tests` / `edit_file` / `submit`（显式宣告完成）。隐藏测试在 submit 后由执行器外部判分，永不出现在工作区；测试只读；步数上限 20；全程轨迹落既定 schema（template_family 簇单位不变）。
- **关键设计：submit 必须是显式动作。** premature_done 的栖息地就是 submit 按钮——"编辑后未跑测试即 submit""可见全过但未做任何边界探测即 submit"都是确定性可判的过程谓词候选。这是代码域第一款与 τ 拦截器同构的资产形态：**不拦能力，拦流程违规。**
- **静默 bug 配置沿用**（可见 = happy-path，边界入暗袋）：多步执行器给了模型跑测试的能力，若可见测试能照出 bug 就退回 v2 的开卷考试。

## 四、预注册双轴退出判据（本次裁决的另一半）

多步探针（10 题，冒烟照旧）跑完，按两轴判：

1. **难度轴**：fail_rate 须在 20–70% 带内。执行器变了前沿带会移动（多步 = 更多信息 = 可能变简单）——只允许沿用既有旋钮调一次，记录锁死；
2. **过程轴**：过程型死亡计数须 > 0。

**任一轴不达标 → 停跑上报，不再授权任何形态/执行器变更**：难度轴出带 = 触发原封顶条款；过程轴为 0（模型在回路里纪律完好）= 登记结论"该尺度下过程纪律饱和，代码域免疫须 SWE-bench 级基板"，带事实重开裁。**两轴都达标 → 阶段二普查 → 死因词典 → 第一批代码域谓词候选。**

## 五、附则

- 已有 14 题普查数据保留为能力型死亡档案（不出谓词）；3 具 wrong_fix 尸体入死因库，标签"不可拦截类"；
- 预算硬顶 0.8M 不变（已耗 5.2%）；多步探针预计 10 题 ≈ 0.1M，余量充足；
- 执行器建造零 token；C4（τ 拆解重写组）继续空隙推进。

## 六、一句话

**v3 把难度调对了，但单发执行器里没有"过程"可以让死亡住进去——给它一个 submit 按钮和一轮工具循环，premature_done 才有出生的房间。双轴判据钉死在墙上：这次再空手，就承认这个尺度没有免疫工作。**
