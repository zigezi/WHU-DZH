**裁决：三个 F 全部成立，且合并诊断出两个新缺陷类（D1 词典过宽误伤普通名词、D2 叙述层与调用层断裂）+ 一个从未立法的池子组成问题（D3 失败 run 的计划在注入池中）。G 门处置：两个减法修复 + 机检验证后开启，免除一轮人工——附触发规则的减法豁免条款。**

## 一、三案 F 复核：全部成立，逐案清理判词

### Case 5（R-081←R-098）：F 成立——本案一处文本藏了三层问题
- **D1 词典过宽**：`"requested two NAME_0x6F4DC8"`、`"NAME_0xD3C1AF 1 succeeded"`——被替换的原文是普通名词（modifications / request 一类）。**普通英语词不是实体，伪真值化它们直接杀死可读性**，这是字典过宽的误伤；
- **D2 叙述层断裂**：`NAME_0xD8BA77`（被改商品名）、`ADDR_0xB85EDF`（旧 LA 地址）只在 summary 叙述中出现、不在调用流中——调用流只含新地址与 ITEM_ID。这**部分是天生的**（叙述按名称讲、调用按 ID 走，层间不要求互指），部分要查提取保真（见 §三）；
- **D3（你问"这是否答案注入"——真正的发现）**：injectant=**R-098，一个在谓词回测里反复锁序失败的失败 run**。它的"计划"是一份失败叙事（改物品成功→订单锁死→改地址失败→转人工）。**失败 run 的计划为什么会注入池？** 现有选择器只看"completed"不看"passed"。这不是答案注入，是**池子组成从未立法**。讽刺注记：这份失败叙事恰好逐字叙述了锁序陷阱——"反面先例"作为警告可能是比成功骨架更好的教具，但那是另一台仪器，登记 backlog（L1.5 负面先例），不进 e8。

### Case 6（R-051←R-019）：F 成立但判词收窄
你判 (a) false 的"突兀"成立（产品名伪值在叙述层漂浮），但"用户名找到 zip 最后找到 id"不是缺陷——`find_user_id_by_name_zip → get_user_details` 是正常链路。金额 $247.87/$646.39 已过机器④可解释性检查。本案的真实成分 = D2。

### Case 7（R-002←R-027）：F 成立，且你的判定逻辑正确
"如果调用了名字转产品 ID 的接口就勉强解释得通，否则 false"——正确。summary 引用多个商品，计划里 `get_product_details` 只出现一次：**要么原始 run 的调用在提取计划时被丢弃（提取保真缺陷），要么叙述层引用无调用支撑（D2 加重）**。这指向一个机检项，见 §三。

## 二、D3 立法：注入池合格性（E 门参数，写入 e8 预注册）

**注入物合格 = 源 run verdict = PASS。** 理由：e8 的 Δ2 假设是"成功骨架迁移"；失败 run 的计划是另一种处理（负面先例），其效应不在本轮假设内。矩阵冻结（E 门）时按 verdict 过滤，过滤前后的池规模变化入报告。

## 三、修复工单（opencode，两个减法 + 两个机检，全部零 token）

1. **D1 修复（减法）**：替换字典加停用词护栏——普通英语词（modification/request/item 类）即使撞上字典条目也不得伪真值化；配套新机检：**每个伪值必须能反查到 DB 实体字典成员**（dictionary membership proof），查不到 = 过宽替换 = FAIL 该单元；
2. **D3 修复（过滤）**：注入池按源 run verdict=PASS 过滤；
3. **提取保真机检（新）**：每份注入物计划的工具调用数与源 run trace 的调用数比对，不一致 → 标提取缺陷记档（不许静默丢调用）；
4. 修复后全库重生成 + 机器④ + 回归集（旧 10 案 + v2 14 案 + 本轮 8 案全部入库）。

## 四、G 门处置与触发规则修订

P5a.39 §四立法"生成器逻辑变更触发人工抽检"。本轮两个修复均为**减法**（删过宽替换、按 verdict 过滤），不引入新文本生成行为，新机检（字典成员证明）可完全机验——**修订触发规则：减法修复经回归集 + 专项机检验证后免除人工轮；加法修复（新增替换类、新文本生成）仍触发。** 本轮适用豁免，人工不再重抽。

处置链：修复 + 机检通过 → **G 门开** → E 门矩阵冻结审查（同域/形态/达标线 + 本节 D3 过滤参数 + 提取保真报告）→ e8 运行令。
