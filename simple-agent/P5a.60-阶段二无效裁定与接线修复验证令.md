# P5a.60 阶段二无效裁定与接线修复验证令

依据：阶段一校准报告（提交 48a4c76 / ff2281b，远端 6e0bb7）、阶段二首跑纪要（18 题，6/18 PASS，tokens=1,854,737）

## 一、阶段二首跑：裁定无效

按 P5a.59 §三停止线，哨兵未实际点火则台账无意义。opencode 自判无效、未把 6/18 PASS 当证据呈递——纪律生效，记一笔。无效原因：τ 工具名带 `tau__` 前缀，名称匹配型守卫按无前缀名匹配 → 静默失效；本轮仅不依赖工具名的 gift_card_balance_enforce_v1 点火 5 次。1,854,737 tokens 定性为接线缺陷的发现成本，登记入账。

## 二、接线缺陷的定性与追溯含义（坏消息扩编）

`tau__` 前缀失配意味着：**自部署之日起，全部名称型守卫（lock_order / items_count_match / non_delivered_exchange / flight_availability_enforce / payment_amount_sum_enforce，共 5 件）从未在活体上点过火**。点火审计的 8/962 扑救、12.3% 良性税，全部是静态回放的"本应点火"。P5a.56 挂账的"lock_order 活体确认"债务扩编至整个名称型舰队；B-3 增 live_confirmed 字段，5 件标 False 并附注记。同时登记历史事件：gift_card_balance_enforce_v1 活体点火 5 次 = 系统史上首次真实活体点火（不依赖工具名匹配，故存活）。

## 三、硬顶不硬是第二个治理缺陷

1.5M 硬顶被穿透 355k 且事后才登记。立法：**硬顶必须是运行时闸**——organ_stage2 增任务间累计检查，触顶即停（SA_BUDGET_CAP，默认 1.5M）。事后账本不算闸。

## 四、对"二选一"的裁决：不做选择题，2→1 串联

零 token 单测验证是重跑的**前置条件**而非替代方案——不验证修复就重烧 1.5M，是拿预算赌一行代码。验证集扩编：5 件名称型守卫**每件**一个 tau__ 前缀 veto 断言，外加原名/非触发负例，全部经真实 execute_tool 路径；全绿后并入常驻金丝雀套件（C-1 每次跑）。修复方案批准：execute_tool 内 gname 归一化后再过守卫，registry 仍收原名。

## 五、出生要件增修（根本立法）

C-1 冷启动门 7/7 全过却漏掉此缺陷——其合成事件未走真实 execute_tool 命名路径，门有保真度缺口。增修：**凡依赖名称匹配的守卫，出生前必须经真实 execute_tool 入口、按生产命名（tau__）过一次零 token 合成点火证明（naming_proof），并入 C-1 出生证行**。堵这一类 bug，不是这一行。

## 六、重跑授权

验证全绿后：新授权 1.5M，批次 10 题（锁死 5 + giftcard 2 + 对照 3），运行时预算闸强制；双目的照旧（目的1 锁序活体确认；目的2 器官活体试产）；一票到底检查照旧（任何 PASS→FAIL 翻转即召回）；无能力声明，只报台账。

## 七、局势评估
