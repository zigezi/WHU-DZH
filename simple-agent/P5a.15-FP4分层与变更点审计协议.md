## 二、FP-4 补丁：结果分层（即刻生效）

裸 token 收窄混合"高效完成"与"少干/失败"两种成因。FP-4 从此按结果分层报告：

- **pass→pass 收窄** = 健康收窄（FP-4 只认这一类为支持证据）；
- **pass→fail 收窄** = 警报，逐条立案；
- **fail→fail 收窄** = 不计分（既非成绩亦非损失）。

## 三、变更点审计协议（替代"全量同任务对比"的提议）

1. 每次 epoch 对比先产 per-task 四象限表：pass→pass / fail→pass / pass→fail / fail→fail（附 token Δ 与两臂归属）；
2. **全链路对比（工具序列 diff + 关键轮 diff + policy 在场性）只对两类做**：全部 pass→fail 变更点；抽样 3-5 条 fail→fail 大 Δ；
3. 对比包由 opencode 准备为结构化 diff，**呈样时隐去其判定**（防锚定协议不变），用户判读；
4. **温度无需比对**（代码冻结保证同一，证据已声明）；**臂归属必须标注**——opencode 须先回答：arm 分配是否每 epoch 重随机？若是，同任务跨 epoch 对比天然混入臂差异，所有变更点对比须按"同臂/异臂"分组判读。
