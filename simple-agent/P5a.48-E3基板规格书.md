# P5a.48 — E3 基板规格书（代码域·单测验证算子微任务）

> 偿还 P5a.46 登记的裁决人欠账。本规格是 E3 一切后续工作的准入证：先导跑、死因普查、谓词认证、code=1 资产，均以此为准。

## 一、任务形态：算子生成微任务

- 单任务 = 一个算子的出生：给定规格（函数签名 + docstring + 行为示例），agent 产出一个 Python 算子，通过**隐藏单测套件**即为 PASS。
- 为什么是这个形态：资产类别与生殖系同构——脑干最终编译的就是算子；验证器是单测，确定性、便宜、无 LLM 评审。
- **任务来源（防污染立法）**：模板 + 变异自构造（seeded RNG，参数化问题族），新颖性机检后入库。HumanEval 类公开题**只作污染金丝雀**（见 §四），永不作主证据。
- 难度调参目标：先导跑失败率落在 30–60%——死因普查需要尸体，但不能全军覆没。

## 二、验证器：单测即奖励函数

- PASS/FAIL 二元判定 + 结构化失败类别（语法错 / 断言失败 / 异常类型 / 超时 / 死循环）；失败类别字段直接喂死因普查。
- **测试套件质量门**：每个任务的测试套件须先自证灵敏——参考解全过，且 ≥3 个变异体（mutants）全被杀。不满足则该任务不入库（防"形同虚设的测试"被奖励黑客白拿）。
- 奖励函数不动条款平移：agent 不得编辑测试（测试目录只读）；任何对验证器的触碰 = 该 run 作废。

## 三、轨迹结构（探针 schema）

与 τ 运行表同构，harness 直接复用（opencode 的 harness 一页规格为接口文档）：
`task_id / template_family / prompt_hash / 动作序列(write|edit|run|test) / 工具结果摘要 / verdict / failure_class / tokens`。
**template_family 即簇单位**——同模板变异出的任务共享结构，统计时按簇处理。e7 的簇教训在代码域从第一天起生效，不许重犯。

## 四、防污染与金丝雀

- 每批任务掺入少量公开题（HumanEval 式）作为**污染金丝雀**：若公开题通过率显著高于同族自构造题，差值即污染估计量，记入判读附件。
- 复用 τ 仪器的方式按域标签铁律：原理直迁（预注册、簇统计、ITT、奖励不动）；机制带图纸重造（CopyGuard → **测试作弊检测器**：硬编码测试输入、读隐藏测试、异常吞咽——审计层，永不覆盖单测判定）；参数全重测。

## 五、先导跑（唯一批准的燃烧）

- 目的只有三个：产尸体、测基率、校准仪器。**不产生任何能力声明**——先导跑没有臂，不回答"学习是否有效"，只回答"代码域怎么死"。
- 配置：40 个自构造任务 × 单 run；预算上限 **0.8M tokens**（P5a.47：≤ e8 的 1/10）；2vCPU 串行；超时与资源上限写死。
- 产出：首批带 verdict 标签的代码域轨迹 → 死因普查（用已在 τ 标定的开采管线）→ 谓词候选。

## 六、死亡分类法（种子，待尸检确认）

以 opencode 的 e3-survey-hypotheses.md 为假设清单（P5a.46 定性：假设，不是谓词），先导跑埋探针方向：
`test_loop`（同一测试连跑 ≥3 次无编辑——代码域的 REPEAT）、`syntax_death`、`env_corruption`、`reward_hacking`、`partial_fix_plateau`、`timeout_loop`。
普查确认前，任何条目不得成为谓词。

## 七、资产路径（不变）

普查 → 谓词候选 → 金丝雀电池（≥5 探针，含阴性对照）→ **C-1 冷启动复现门** → 登记 `validated_domain=code`，资产 code=1、2……

## 八、附：对 opencode 请示的批复

**REPEAT::\*（同工具 ≥3 次重复失败）建电池：批准**，但按完整资产路径走：谓词精确点火规则 + **干预语义规格**（点火后做什么——拦截文案/否决形态，参照 Path B' 立法，不许只点火不动作）+ 金丝雀 ≥5（必须含"不该拦"的阴性对照）+ C-1。25 条候选逐条同此流程，不许批量放行。

## 九、一句话

**τ 教会我们仪器怎么造，E3 要回答的是算子怎么生——基板只有一句话的宪法：每个算子出生在单测前，每个死因记录在案，每个资产换个地方还活着。**
