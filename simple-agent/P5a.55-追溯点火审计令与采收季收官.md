## 二、追溯点火审计（零 token，新工单）

金丝雀电池证明"该点的会点、合成的不该点不点"；但有一个问题金丝雀回答不了：**在真实历史轨迹里，这些谓词的点火行为是什么？** 静态回放 e1–e8 全部轨迹（不跑模型，纯日志演算）：

**每资产输出一张混淆矩阵**：

| | 该点火 | 不该点火 |
|---|---|---|
| **点了** | 救场计数（命中其死因类型的 FAIL run） | **真实误伤（命中任何 PASS run）** |
| **没点** | 漏报（其死因类型但没点到） | 正常沉默 |

**预注册通过线**：

1. **真实误伤 = 0 是硬线**——对任何 PASS run 点火 = 设计缺陷，该资产回炉（金丝雀的阴性对照漏了真实世界的某种合法形状，找出它、补进电池、再审计）；
2. 救场覆盖报告：对其死因类型的 FAIL run 的点火覆盖率（应 ≈ 普查计数，例如 lock_order_v1 对 6 条 lock_order 先例应全中）；
3. 顺带产出：**每个资产的"历史救场数"——免疫系统第一个真实 ROI 数字**（若历史重演，8 个资产共能改写多少具尸体的结局）。

**通过者升级**：credit_level 从 T1_candidate 升 **field_validated**（B-3 schema 加此等级值；溯源层记录审计证据）。
