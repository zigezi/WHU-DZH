# P5a.47 — τ 残值清点与冷启动复现门立法

> 触发：用户问——先去代码域验证学习有效性再回 τ？还是 τ 还有可提供给免疫系统的部分，做完再上代码域？
> 裁决：**假二选一。τ 有一笔零 token 的残值必须收（失败开采），E3 规格并行推进；不存在"回 τ 验证学习有效性"这一站。用户提出的"换台服务器还能不能完成 τ"采纳并立法为 C-1 冷启动复现门。**

## 一、拆开两个混淆

**混淆 1：资产域 ≠ 管线域。** "先在代码域证明学习有效性，再回 τ 证明学习有效性"——学习有效性不需要换域证明，它等于一个可观测事实：**认证过的资产在新 run 里点火了、拦住了本来会死的案例**。资产是域专属的（validated_domain 铁律：代码算子帮不了客服任务，反之亦然）；管线是域无关的。跨域迁移的是管线与 harness，不是资产。所以正确的提问不是"回 τ 验证学习"，而是"**开采→谓词→金丝雀→部署**这条管线在哪标定最便宜"。

**混淆 2："学出东西"的形态。** 本架构里没有"改写权重"这回事——资产是代码与谓词，不是梯度。自创生在本系统的操作定义 = **免疫认证的资产持续累积、且每个资产可被独立复现**。这正好引出用户自己的提议。

## 二、采纳并立法：C-1 冷启动复现门

用户的"换台服务器还能不能完成 τ"直接命中他自己第四轮的存在性恐惧（"是我在黑板上修 bug 修出了幻觉，还是它真的过滤筛选出了东西"）。这是区分两者的**唯一决定性实验**，立法如下：

- **C-1 冷启动复现门**：全新环境（新服务器或干净容器），只装入 资产注册表 + harness + τ 环境，不带任何会话历史/本地卷宗；跑锁死 5 任务型或 B-2 金丝雀电池；**lock_order_v1 点火且拦截正确 = 资产是真实可移植的物，不是黑板幻觉的投影**。点不火 = 部署环节存在隐性会话依赖，资产证书记假，回炉。
- 每个新资产登记后都必须过 C-1，列为出生证的最后一栏。
- 成本：零模型 token（金丝雀/锁死任务的判定是确定性的）。

## 三、τ 残值清单（全部零 token，做完即枯竭，不再续约）

1. **失败开采管线首次实跑**（P5a.36，scripts/p5a36_failure_mine.py）：e1–e8 的尸体库是现成的最大财产。产出 τ 死亡模式谓词词典 → 候选 → 金丝雀 → 资产 τ=2、3……。**双重收益：既喂发热比的分子，又在最便宜的已知地形上标定开采管线本身**——这条管线正是 E3 代码域普查要用的仪器，先在 τ 上把刻度刻好。
2. **lock_order_v1 干预日志**：未来任何 τ 运行中自然累积，形成第一份资产纵向行为数据集（资产在野外的真实点火率/误伤率）。不专项烧钱，只记录。
3. **τ 保留为冷启动床**：135 任务 + 确定性判分 = 全场最便宜的 C-1 考场。
4. **L1.5（负先例）与 B-3（溯源层）**：域无关仪器，在 τ 上建造最便宜。

τ 不再提供的东西（维持 P5a.44/45 冻结）：epoch 级假设检验、注入机制任何变体、任何百万 token 级燃烧。

## 四、序列（立法）

```
τ 失败开采实跑（opencode，零 token）  ∥  E3 基板规格书（裁决人欠账）
        ↓
τ 资产 τ=2..n 出生（各过金丝雀 + C-1）
        ↓
E3 先导跑（预算 ≤ e8 的 1/10，另批）→ 代码域死因普查（用已标定的开采管线）
        ↓
代码域资产 code=1..（各过金丝雀 + C-1）
```

没有"回 τ 验证学习"这一站。τ 的最后一班岗是当冷启动床。

## 五、一句话

**τ 还没死透——尸体库里还埋着资产；但尸体采完就封矿。至于"换台服务器"：那是好得超出你本意的主意，从此每个资产的出生证最后一栏都是同一句话——换个地方，它还活着。**
