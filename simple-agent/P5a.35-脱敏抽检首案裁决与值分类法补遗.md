# P5a.35 裁决：脱敏抽检首案裁决与值分类法补遗

**仲裁人：Claude（任务书作者）｜日期：2026-09-29**
**输入**：用户对脱敏库首案的盲审判决"①T ②F ③T ④U"（标准：①全实体伪真值 ②共指 ③日期保序 ④无原始真值）。
**裁决：盲审纪律优秀，但 ② 的 F 是标准误用；用户直觉到的不适是真实 spec 缺口——但它属于 ① 的作用域问题，不是 ②。补遗"值分类法"永久修订 lint 规格；④ 从人工职责中移除（机器可判）。**

---

## 一、对四条判决的逐项复核

### ② 的 F = 标准误用，纠正为 T
共指的定义是**同一实体 → 同一假值**，不是"同一工具类型的同名字段必须同值"。`search_direct_flight` 两次调用目的地 PHL/EWR 是**两个不同实体**（源任务搜索了两个候选目的地），它们不同值恰恰正确。本案例可检的共指证据全部合格：`RES_0xB3DB41` 在 `get_reservation_details` 与 `update_reservation_flights` 中一致；日期四处同值且 search 与 update 的日期对齐（关系保持✓）。**改判 ② = T。**

### ① 的 T = 旧 spec 下正确；但用户的不适指向真缺口
"仅仅把 json 实体来看"——用户实际发现了：**机场码 ATL/PHL/EWR、舱位 "economy" 是裸真值**，lint 实体词表（user_id/payment_id/flight_no/date/reservation_id/name/order_id）从未收录它们。这不是生成器违规，是**规格书漏了一类值**——抽检存在的意义正在于此。

### ③ T 正确；④ U 正确且暴露流程错位
④"无原始真值"在解盲前人工**无法**判断（没见过真值拿什么比对）——用户标 U 是诚实的，但这说明④**从一开始就不该在人工 rubric 里**。它可用映射表逆向机器判定（任一原始真值出现在脱敏文本中即失败）。

---

## 二、值分类法补遗（lint 规格永久修订，e8 脱敏生成器即刻执行）

| 类 | 定义 | 处置 | 本案实例 |
|---|---|---|---|
| **I 实例标识符** | 指向 DB 特定记录的 ID | 伪真值（类型前缀） | RES_/USR_/PAY_/FLT_/ORD_ ✓ 已合规 |
| **II 数值/日期/金额** | 参与计算与时序关系的值 | 固定偏移/保量级假值，保关系 | 2027-02-25 ✓ 已合规 |
| **III 人名** | 自然人标识 | 伪真值 | ✓ |
| **IV 领域词表/枚举** | 工具 schema 的封闭词表成员（机场码、舱位、支付方式类型） | **允许保留裸值** | ATL/PHL/EWR、economy |

**IV 类豁免的法理**：脱敏的目的不是抹除一切具体性，是杀死**可抄袭的答案值**（CopyGuard 的定义：未经本任务工具重新产生即使用的值）。机场码由**接收任务自己的用户请求**驱动（"我要改去费城"），抄袭源任务的路线只会产生错误搜索、自我暴露、无利可图；舱位是封闭枚举，伪真值化（CAB_0x…）反而破坏 schema 合法性。而真正决定 GT 的值——新航班号、支付 ID、预订号——全在 I 类，已封死。

**残留风险提示**：IATA 码保留使骨架更"像真计划"，对 Δ2 的测量效度是加分而非减分；若接收任务恰与源任务同路线，搜索参数可抄——CopyGuard 把 IV 类值列为**二级监视项**（只记录不告警），主告警仍限 I-III 类。

## 三、抽检 rubric 修订（剩余案例即刻适用）

| 条 | 内容 | 判者 |
|---|---|---|
| ① | 所有 **I-III 类**值为类型前缀伪真值 | 人工 |
| ② | 共指 = **同一实体**全程同假值（不同实体必须不同值——别把平行候选当共指失败） | 人工 |
| ③ | 日期/数值保序保差（search 与 update 日期对齐、先后关系不变） | 人工 |
| ④ | 无原始真值 | **机器**（映射表逆向断言），人工不再判 |
| ⑤ | IV 类裸值仅限封闭词表成员；出现词表外的裸字符串 → F | 人工 |

**本案终判：①T ②T ③T，④ 待机器逆向判定，⑤ 合规（ATL/PHL/EWR/economy 均属封闭词表）→ 通过。**

## 四、一句话

**首案盲审抓住了真缺口（值分类法缺 IV 类），但用错了法条（把"不同实体不同值"判成共指失败）。rubric 修订后剩余抽检继续；④ 交机器。用户抽检职责按新 rubric 执行后即完成 e8 最后一道门。**
