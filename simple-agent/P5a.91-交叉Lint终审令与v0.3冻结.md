## §一 提示词模板 v1.1（冻结）

采纳 DS 两项 + Qwen 行号补丁，冻结形态：

1. **证据形式 = 原文片段（quote ≤50 字）+ 章节路径**，行号废除。Qwen 的「坐标系陷阱」成立：行号依赖抽取工具（pdftotext/PyMuPDF/pdfplumber 各行其是），尺子与被试坐标系错位会制造假 FAIL——仪器缺陷污染 RQ1 读数。quote 是工具无关锚。评测器侧匹配纪律：空白归一化后子串匹配。
2. **核查清单 = 纯陈述句**（DS）：「申请书第三部分与实施方案第五部分数值等同」✓；「请比对预算」「注意单位换算」✗。
3. **任务型名称严格映射**，零修饰词。
4. **钉界**（防未来争议）：核查清单是**任务规格（查什么）**，不是方法（怎么查）——真实评审中招标方同样下发符合性审查表，清单下发不构成外源结构注入。

## §三 评测器纪律两则（立法，入评测器规格书）

1. **结构化参数通道**（Qwen）：任务输入中的阈值参数以 JSON/YAML 附录字段下发评测器（如 `{"credit_report_validity_months": 3}`），**评测器严禁解析自然语言段落**；自然语言给被试看，结构化字段给裁判用——「裁判读卷」的格式钉界。
2. **白名单读取 + 静默丢弃**（Qwen）：解析 agent 输出时只读规定字段，多余字段（思考过程、检索链接等）一律静默忽略，**不得因未知字段触发 Schema 崩溃或判死**——ITT 分母完整性是评测器底线。
3. **Env_Missing_NA 标记**（DS 提出，Qwen 附议）：smoke 期 R3.5 因榜单通知缺失触发的 NA，尸体台账必须标记为环境缺失合法 NA，**严禁计入操作者能力缺陷**。
