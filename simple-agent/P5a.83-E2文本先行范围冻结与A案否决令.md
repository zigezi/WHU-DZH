# P5a.83 — E2 文本先行范围冻结与 A 案否决令

**案由**：用户就 E2 多模态需求提出 A/B/C 三案（A=硬件升级+管线接入+监控大改；B=另寻确定性数据集支撑 E2 建设；C=前提有误则指出并给答案）。用户前提含两处错误，本席启用 C，并给终局答案。
**依据**：P5a.81（E2 任务书骨架）；P5a.68（校准投毒禁令）；P5a.80（版本漂移与 env_fingerprint 纪律）；P5a.33（脱敏纪律）；安全约束（密钥纪律全文）。

## §一 前提勘误（启用 C 案）

**错误一：「API 调用违背我们自己的判决」——查无此判。**

翻遍全部在案判决与安全约束，被禁止的是：密钥入代码/提交/证据/日志（DC-7 立法）、git push（RL-3）、捏造、未经脱敏的敏感映射外流（P5a.33）。**没有任何一条禁止外部 API 调用。** 反证就在系统自身：opencode 的骨干就是 API 调 DeepSeek V4.1 Flash，Qwen3.8-Max 的面试与体检也是 API。若 API 调用违法，这个系统从 a0 起每一回合都在违法。

**错误二（由错误一推出的假约束）：「提取全流程尸体必须自己部署印章/视觉模型」。**

此约束仅在「文件内容一个字节都不许离开服务器」成立时才成立。但注意：**E2 的智能体要读投标文件，文本层无论如何必须经骨干 LLM（API）处理**——这是 E2 存在的前提，不是可选项。若真立「零出域」规则，要自部署的就不是印章小模型，而是整个骨干 LLM，A 案的硬件升级将从「买个 GPU 跑视觉」膨胀成「重建整个推理栈」，E2 直接判死。若接受文本经 API（现状即如此，脱敏纪律约束之），则图像/印章是否走 API 只是同一条纪律下的同类决策，不构成「必须自部署」的理由。

**真正的在案约束只有两条**：(i) 脱敏先行，映射表本地不落证据（P5a.33）；(ii) 预算经运行时闸。这两条对文本和图像一视同仁。

## §二 本席认领一处措辞过失

上轮本席称「纯 md 会把图像和印章这两类死亡源**阉割**掉」。此语把**增益轴**说成了**必需品**，是本次误读的源头，予以更正：

翻 P5a.81 冻结文本——§四有用性判据四条（ITT 可信基线 / 尸体产量与死因多样性 / ≥1 资产全生命周期 / 零硬线违例）、§七成功定义，**无一字要求多模态**。死因多样性判据由文本层即可满足：格式硬校验失败、数字一致性失败、章节缺失、上下文漂移、预算耗尽、超时、pdf 文本抽取失败（合法的环境/工具类死亡）——七个潜在死因类，多样性绰绰有余。印章/图像是锦上添花的第八、第九类，不是门槛。

## §三 A 案否决

**否决硬件升级 + 功能管线接入 + 监控系统多模态大改。** 理由三条，各自独立成立：

1. **服务于非目标**：epoch-1/2 的任何预注册 RQ 与判据都不需要印章/视觉能力（§二）。为一个无人要求的死亡源花真金白银+数周工期，是范围爆炸。
2. **破坏实验连续性**：a80 立法尸体绑定 env_fingerprint，smoke 先导（3-5 题）的成本模型标定在现机器上。中途换硬件 = 成本模型作废重标 + env_fingerprint 断代，epoch 间可比性受损。
3. **当前真瓶颈不在此**：尸体农场的真实瓶颈是代码域真尸 6/30 与 E2 三项域事实，不是缺多模态。资源投向瓶颈之外即浪费。

**处置**：多模态（含印章核查）登记为 epoch-3+ 候选议题，届时若 epoch-1/2 数据证明文本层死因多样性不足，可单独立 E 门审议。门禁保留，不等于路线承诺。

## §四 B 案部分采纳，角色修正

用户直觉方向正确（确定性数据集有用），但**角色必须修正**：

- **E2 语料：仍必须是真实历史投标文件**（a68 校准投毒禁令延伸至语料层）。合成语料做基线 epoch = 在仪器上乱扭。
- **确定性数据集的正确岗位 = 评测器校准夹具**：取真实文件，程序化注入已知缺陷（删必备章节 / 篡改数字使其不一致 / 破坏格式），得到已知答案集。用途有二：(i) 标定评测器 (a) 确定性结构检查与 (b) LLM 评审的灵敏度/特异度——这就是评测器的 naming_proof；(ii) 器官电池的 fixture 来源。**夹具只证明仪器，不进基线 epoch 统计，不算尸体来源。**

这与金丝雀门的关系：金丝雀门已有已知答案夹具纪律，缺陷注入集是同一纪律向评测器的延伸，不是新机制。

## §五 E2 文本先行范围冻结（epoch-1/2）

1. **语料**：真实历史投标文件，docx + pdf（保留 pdf 是为版式多样性与抽取失败这一合法死因，不要求读图），脱敏先行。
2. **任务定义四类不变**（a81 §八.2）：章节补全 / 合规检查 / 数字一致性核对 / 全文审查。**明确排除印章与签章页核查**——该项依赖视觉能力，出 epoch-1/2 范围。
3. **评测器**：(a) 确定性结构检查（必备章节、格式、数字一致性——文本层完全可做）+ (b) LLM 评审 + rubric + 人工抽检锚（P5a.35 模式）。评测器上线前过 §四 缺陷注入夹具标定，灵敏度/特异度入证据。
4. **监控/采集**：现有工具层钩子 + 回合末收割 + 任务级判定通道，零改动复用。a82 §五 的钩子加固照旧，与多模态无关。
