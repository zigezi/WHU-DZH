## 二、质询裁定：判例驱动的代码修改不会使尸体失去可分析性

分析的三层对漂移的关系各不相同，逐层拆：

1. **开采/分诊 = 日志内容分析**（命令、退出码、stderr、死因类）——不依赖代码版本，漂移免疫；
2. **谓词/金丝雀电池验证 = 对当前代码的合成夹具复现**——电池传统就是自生条件而非回放历史，漂移无关；
3. **死因语境理解**（"当时为什么死"）——唯一依赖历史状态的层，用锚定解决：尸体条目绑定**采集时刻的 git HEAD hash + env_fingerprint（B-1 已有设施）+ schema 版本**。需要回到历史语境时 `git archive <hash>` 即可重建，不靠当前代码兼容旧尸体。

先例在案：a73 法医实证过漂移（e3 产物不可复现），当时的答案是 attic + 溯源；本次是同源逻辑的向前延伸。
