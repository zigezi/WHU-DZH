## 二、定性：召回缺陷，非精度缺陷（DC-10 立案）

### 2.1 机器预扫"0 残留"为何被证伪

残留扫描的探针口径是"**映射表中的已知值是否回现**"——它只能看见已经入表的标识符。本次泄漏的三类 PII **从未进入映射表**，对残留扫描天然不可见。故"0 残留"是**空真（vacuous truth）**：精度侧（遮了的没漏）成立，召回侧（该遮的都遮了）从未被检验。

### 2.2 泄漏三形态登记（修复靶点）

1. **水印散布单字**：信用报告下载平台将下载者姓名与时间戳烧成斜向水印，文本层表现为跨页高频孤立单字/数字碎片（周、学、婷 + 日期碎片）。整词正则对此形态**结构性失效**。
2. **语境位人名**：股东、监事、法定代表人、CTO、联系人等语境位的人名（姜美娟、周星），脱离"姓名："等显式标签时未被识别。
3. **短名与变体**：全称入表后，其字号级子串（兔展智能、深圳兔、兔灵）未并入映射，且出现"深圳兔【COMPANY-XXX】"的**半遮蔽**病态形态——遮蔽边界未按完整 token 切分。

### 2.3 立案与责任划分

- **DC-10：脱敏器召回失效（漏遮蔽）**。类别：**仪器缺陷**，非操作者缺陷。
- **规格缺口在裁者，不在执行方。** a87/a88 立法的机器断言规格只覆盖精度侧（映射解释 + 行数守恒 + 标题守恒），未立召回探针。opencode 按已批规格执行，且预扫报告如实标注了口径（"对映射值的残留命中"），无夸大、无隐瞒——**不罚，记诚实口径 +1**。规格缺口登记**裁者台账第 4 笔**：凡断言"干净"的验证，必须先问"探针覆盖到什么"。

### 2.4 制度兑现登记

人工抽检锚首战立功。机器自证清白被人工锚证伪——P5a.35 / LR-1 教义（仪器自报须有锚）再次兑现，且兑现于**冒烟点火前夜**，这正是锚存在的意义。登记为章程级案例。

a. **语境触发器**：法定代表人 / 股东 / 监事 / 成员 / 首席技术官 / 联系人 / 负责人 / 教授 / 博士等语境位之后的中文人名候选（2–4 字）进入遮蔽候选集。
