## 一、第一问：always_na 实现机制（声明式抑或命令式）——登记，非阻塞

**教义提炼（常设）**：指纹 = 冻结后完整性的护栏；内容审计 = 冻结时内容的护栏。两者正交，缺一不可——这正是第二问的战场。

## 二、第二问：提示词 v1.0 → v1.1 的 Diff 审计——**采纳，阻塞级，新增点火前清单 #11**

### 2.1 定性

Qwen 的区分精确且致命：**指纹证明"没被篡改"，不证明"内容本身无注入"**。a91 我签冻结令时，验收动作是"立法补丁 + 指纹重钉"，**从未命令人工或机器对 v1.1 全文做逐字 Diff 审计**。若 v1.1 在"行号 → quote"之外夹带任何额外措辞（方法提示、单位提示、语气引导），即构成 a85 §三 红线所禁的**外源结构注入**——提示词是喂给被试智能体的，夹带提示 = 污染基线 = e8 式事故。

**裁者台账第 5 笔**：版本冻结验收规格缺"逐字 Diff"要求，与第 4 笔（召回探针缺口）同族——**验证器自身的验收规格不全**。登记，不辩护。

### 2.2 立法：点火前清单 #11（阻塞项）

1. opencode 出具 **v1.0（P5a.89 §一 所刊原文）↔ e2_prompt_v1.1.md 全文的逐字 Diff**，随 DC-10 修复回执一并提交。
2. **唯一许可变更** = a91 立法项：证据形式由"章节名或行号"改为"原文 quote（≤40 字）+ 章节路径（不用行号）"。
3. Diff 出现任何此外的措辞差异 → 判定外源结构注入 → 提示词退回重做、指纹重钉、重新走 a91 双签程序，smoke 不得点火。
4. **确认人 = 用户**（人工锚；Diff 由 opencode 生成，确认不可代理）。
5. **常设化**：此后提示词 / 规则集 / 评测器的任何版本跃迁，changelog 必须附逐字 Diff（大文件可节级 Diff），不接受摘要式变更说明。写入变更控制条款（a90 修正案）。

## 三、第三问：水印判别的假阳性风险——**采纳，折入 DC-10 验收标准**

### 3.1 风险确认

DS-Qwen 合谋指出的链条成立：若"跨页 + 孤立 + 高频 + 单字"触发条件不含姓氏停用保护，**真实签署人名（尤其单字签名场景）可能被误判为水印而删除** → R1 结构检查将判"签署字段缺失" → **仪器制造的假尸体** → 直接污染基线科学结论。这比 a92 已登记的"空行化微弱副作用"严重一个量级。风险确认为真。

### 3.2 立法：连续出现判别器（水印清除的触发条件升级）

水印清除**仅**适用于同时满足下列三条的字符集合：

a. 仅以**孤立单字 token** 形态出现（不成词、不成行内连续串）；
b. 该字符集合在文档正文**任何位置均不连续共现**（全文检索不到相邻排列）；
c. 同一固定集合**跨 ≥3 页**重复散布。

**判别规则的推论**：集合一旦在任何位置连续出现（如"姜美娟"在股东表连续成词），即判定为真实人名 → 走【PERSON-XXX】遮蔽路径，**禁止走清除路径**。此条同时正确处置本批两案：周学婷（仅散布、从不连续 → 水印，清除 + 映射表登记 watermark 条目）；姜美娟（连续出现 → 遮蔽，不删除）。

**铁律**：签署字段永不删除。签署是 R1 任务荷载（申请书七声明含签署项），任何仪器不得以减少字段的方式"净化"文档。

### 3.3 回执披露项（opencode，随修复回执提交）

- 停用表全文（是否含常见姓氏）；
- "孤立"的精确定义（行内孤立 / 页面孤立 / token 级判定）；
- 区域约束（是否仅页眉页脚触发）；
- 触发逻辑伪码。

### 3.4 召回 fixture 增补两案

1. **共存案**：同一文档内"连续签名（甲名）+ 散布水印（乙名）"并存 → 要求签名以代号形式存活、水印整带清除，二者路径不得互换。
2. **重合案**：水印集合字符与正文常用字重合时，判别器仍依 b 条（连续共现检测）正确分流，不得误删正文用字。

两案 100% 通过方可重新 deployed。

### 3.5 #9 复检规程增补常设项

用户人工复检时，除 a92 §五 各项外，**显式核查"签署字段以代号形式存活、未被清除"**（适用含签署页的文档类型）。
