## §二 规则集 v0.1（预注册草案 → 用户领域评审 → 冻结 + 指纹重钉）

**R1 结构必备（按文档类型 × 模板，模板识别先行）：**

- 申请书模板：填表声明与保证七条（真实准确完整 / 知识产权无失信 / 专用用途 / 授权使用信息 / 注册地不迁出 / 未入失信名单 / 送达地址）+ 第一/二/三部分齐全 + 签署日期字段存在。
- 实施方案骨架：一、场景需求理解（含子项 1 场景名称·地点·周期 / 2 行业现状 / 3 技术突破）；二、建设单位；三、合作模式；四、实施计划；五、经费预算（单位：万元）。
- 信用报告双模板：信用广东版（十类信息清单）与深圳信用网版（基本信息及子项）——先识别模板再套清单。

**R2 数字勾稽：**

- R2.1 表内（附件3-2 型）：合计 = 直接 + 间接；直接 = 五项之和；小计 = 财政 + 自筹；自筹 ≥ 资助申请额。
- R2.2 跨文档：申请书「第三部分：项目预算」 ≡ 实施方案「五、经费预算」 ≡ 概算附件（若存在），逐行相等。
- R2.3 单位纪律：默认万元；¥ 前缀、大写中文数字、逗号分隔按单位归一表换算后比对。

**R3 维度合规集合逻辑（初稿六条，普查实证）：**

- R3.1 IF 申请书含项目预算 THEN 实施方案必含经费预算（同值）。
- R3.2 IF 申请书声明知识产权无失信 THEN 信用报告「严重失信主体信息」须为 0 条。
- R3.3 建设周期须为闭区间，签署日期 < 周期起。
- R3.4 IF 实施计划含阶段月份 THEN 各阶段须落在建设周期区间内。
- R3.5 信用报告数据更新时间须早于申请书签署日期且在合理有效期（≤6 个月，评审实务值，用户可裁）。
- R3.6 申请书与实施方案的场景名称逐字一致。

**R4 判定输出**：逐规则 PASS / FAIL / NA + 证据行号。NA 须有文书依据，禁滥用。

## §三 epoch 任务集生成规则（参数化，预注册冻结）

1. 每文档任务模板：申请书 → T1 + T3（2 题）；实施方案 → T1 + T3 + T2（3 题）；信用报告 → T1（1 题）；概算附件 → T2（1 题）。
2. 多样性轴：篇幅三档（长 ≥40p / 中 8-30p / 短 ≤7p）各 ≥20%；类型配比 T1:T2:T3 ≈ 4:3:3。
3. 语料规模 N 到位后：实例**机械生成、禁止挑选**，全量清单进 E 门包并绑指纹。N ≥ 10 件即达 20 题下限。
4. epoch 预算 = smoke 成本模型 × 实例数，E 门审议。
