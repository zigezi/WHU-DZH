# P5a.50 — 基板变体 B 授权与难度前沿带原理

> 触发：E3 阶段一校准探针实测失败率 0.0%（两轮：带示例 / 去示例——唯一一次调整已用尽并锁死），金丝雀差分 0。opencode 按纪律停跑等裁。
> 裁决：**驳回"暂缓代码域"；批准任务形态层面的加难——基板变体 B（修 bug 形态）为 v2 主形态，阶段一重跑授权，预算沿用 0.8M 硬顶（已耗 2,237 tokens）。**

## 一、判读：0% 失败是什么

- 这不是"模型太强所以 E3 失败"，是**基板形态低于该模型的能力地板**：单发函数合成（签名+doc+示例 → 一个函数）对现役模型已饱和，HumanEval 式微任务的天花板早就到了。金丝雀差分为 0 同理——公开题和自构造题在这个难度下都被秒，污染仪器在低难度下无读数。
- 确认 opencode 的判断：难度问题出在**任务形态层**，参数调整（去示例）够不到。选项 2（代码域暂缓、τ 足够）驳回——τ 的死亡类型已采尽，代码域死因词典是生殖系的必需品，缺的只是正确的解剖台。

## 二、立法：难度前沿带原理（本裁决最重要的产出）

**免疫系统只在"可拦截的模式化死亡"存在的地带工作。** 由此推出基板设计的筛选标准：

1. **死亡按可拦截性分两类**：过程性死亡（test_loop 空转、partial_fix_plateau、premature_done 未跑测试就宣称完成、regression_break 修好一个弄坏一个、env_corruption）——**可拦截**，是谓词的猎物；能力天花板死亡（想不到 DP 递推、解析算法不会写）——**不可拦截**，拦截器拦不出能力，此类尸体对资产管线无营养。
2. **基板难度必须骑在模型的能力前沿带上**（失败率 20–70% 的操作化定义），且**难度是模型相对量，不是绝对量**——模型换代，基板必须重新校准。本条列入 E3 永久纪律。
3. 由 1 直接裁定三个候选形态：**(b) 多步"读坏代码再修" = 主形态**（过程性死亡的全部栖息地）；**(a) 只给失败测试不给签名** 吸收为变体（推断规格，仍是单发合成，难度增量有限）；**(c) DP/解析难族驳回为主方向**——尸体多是能力型，喂不出谓词。

## 三、基板变体 B（v2）设计要点

**任务形态**：给一个带注入 bug 的小型模块 + 隐藏单测套件；agent 读代码 → 跑测试 → 定位 → 修 → 复跑，全过即 PASS。这就是代码域的"状态变更型任务"，τ 锁死陷阱的同构物。

**关键的免费午餐——变异体复用**：测试灵敏度门（P5a.48 §二）本来就要为每个族生成 ≥3 个"被杀的变异体"。**这些变异体就是现成的"带标准答案的坏代码"**——任务 = 变异体模块 + 隐藏测试；修复目标 = 参考解。生成器几乎零新增成本，且注入 bug 的变异算子类型成为**免费的死因先验标签**（尸体还没产生，分类学先验就有了）。

**难度旋钮（真正的可调参数）**：变异算子的微妙度（off-by-one → 逻辑反转 → 边界条件）、注入 bug 数（1→2）、模块行数、可见测试比例。校准探针从"单 bug + 明显变异算子"起步。

**纪律沿用**：两阶段（10 题探针 → 出带只许调一次并锁死 → 30 题普查）、C3 报告模板不变（禁能力声明）、冒烟测试先行（桩 agent 喂变异体原样 → 必须 FAIL；喂参考解 → 必须 PASS）、簇单位 template_family 不变。

- v2 建造（变异体→任务装配层）零 token；建成后重跑阶段一；
- C4 拆解重写组案头工作继续挂起至 v2 探针点火。

## 五、一句话

**v1 证明了这个模型的地板在哪——好消息，以后不用在那里埋探针了。免疫系统要住在能力前沿上：太低没有尸体，太高尸体没有营养。把灵敏度门杀掉的变异体端上桌——它们天生就是带死亡证明的教具。**
