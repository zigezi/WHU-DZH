# P5a.46 — E3  sequencing 裁决与"凭空起草谓词"驳回

> 触发：opencode 请示 E3 首个交付物（代码域死因普查），请求用户提供代码域任务来源，或"先按通用代码任务起草候选谓词集"。用户问：为什么不能用 ep1–8 的 τ 记录。

## 一、先清账：e9 与 E3 是两回事

- **e9 已结案**：lock_order_v1 已部署（资产 τ=1），发热比从 ~30:0 变为 ~30:1。它不需要任何新数据——死因来自 P5a.28 回测，验证来自 B-2 金丝雀电池，都已交付。
- opencode 请示的是 **E3（代码域）**，一个全新域。τ 的 ep1–8 探针记录记的是 τ 域的死法（客服工具调用的锁序陷阱等）；代码域的病理完全不同（测试空转、构建破坏、奖励黑客、环境污染）。**`validated_domain` 立法在案：死因词典过境即作废，跨域复用未再验证的资产 = 把噪声当经验。** 这就是为什么要新数据——不是记录不干净，是域不同。

## 二、对 opencode 两个选项的裁决

**选项 1（请用户提供代码域任务来源）：方向对，但问早了半步。** E3 缺的不是"一份干净的任务-代码-执行记录"——那东西不存在于任何已有数据里，它只能由 E3 基板自己跑出来。所以第一步不是找数据，是**基板规格**（已登记为裁决人欠账）：任务形态（单测验证的算子生成微任务）、验证器（单测即奖励函数）、人口规模、防污染策略（自构造题优先）。基板定了，跑一次小规模先导，第一批"尸体"自然产生，然后才轮得到死因普查。

**选项 2（先按通用代码任务起草候选谓词集）：作为谓词来源驳回。** 凭"对代码失败的想象"起草谓词 = 黑板行为——谓词必须出生于尸体（真实轨迹中的死亡病例），这是证据驱动教义（P5a.17 四字段提案须有观测证据）和 P5a.36 失败开采管线的根基。**收留形式**：该清单可提交，但只能标记为"普查设计假设清单"，作用是指导先导跑时往哪些方向埋探针；任何条目未经观测死亡 + 金丝雀电池认证，不得成为谓词，不得登记资产。

## 三、E3 执行序列（立法）

1. 裁决人出 E3 基板规格书（欠账，优先偿还）；
2. opencode 按规格建基板，小规模先导跑（预算另批，量级 ≤ e8 的 1/10），产出第一批带单测判定标签的代码域轨迹；
3. 死因普查（选项 1 的真正开工点）→ 谓词候选 → 金丝雀电池 → 登记 `validated_domain=code` 的第二个资产。
